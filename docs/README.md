## 現在のフォルダ構成

```text
LossLandscape/
├── AGENTS.md                      # Agent との共通作業規約
├── README.md                      # プロジェクトの入口
└── docs/
    ├── README.md                  # 資料案内と配置方針
    ├── TODO.md                    # 作業順・進捗・未決定事項
    ├── EXPERIMENT_PLAN.md         # 研究・評価設計の草案
    ├── IMPLEMENTATION_SPEC.md     # 実装仕様の草案
    ├── REFERENCES.md              # 参考文献・参考実装のリンク集
    └── examples/
        └── config_example.yaml   # 検討用の設定例
```

ルートには概要を残し、詳細資料を `docs/`、説明用の設定例を `docs/examples/` にまとめています。資料数が少ないため、研究用・実装用の細かなサブフォルダにはまだ分けません。

[AGENTS.md](../AGENTS.md) は作業規約としてルートに保持し、内容は変更していません。研究計画・実装仕様・設定例の草案とは区別して扱います。

ユーザー許可のもとで行ったGPU・B256の短いメモリ確認は、[実装仕様案の環境確認記録](IMPLEMENTATION_SPEC.md#21-environment-check-2026-08-31) に記載しています。実データによる学習や研究結果の検証ではありません。

## 将来のフォルダ構成について

コードや実験データの配置案は、[実装仕様案の Suggested Repository Layout](IMPLEMENTATION_SPEC.md#3-suggested-repository-layout) にまとめています。

`src/`、`scripts/`、`tests/`、`configs/`、`data/`、`artifacts/` は現段階では作成していません。実装範囲が決まった時点で、必要なものから作成します。設定例は資料として保持し、そのまま確定済みの実行設定とは扱いません。

## 今後の検討事項

- 研究対象、モデル、比較条件、フェーズの範囲と優先順位。
- 学習条件、実行回数、保存頻度、可視化の計算量。
- 設定例と実装仕様の整合。例えば、checkpoint の保存間隔は設定例では epoch 単位、実装仕様の dataclass 案では step 単位になっています。ここではどちらにも統一していません。
- 相対パスの解決方法、実験ごとの成果物の保存先、実装用フォルダの詳細。

今回の整理では、元資料の研究内容や設定値は変更せず、配置・リンク・草案としての位置づけを整えています。今後も、提案と決定事項を区別して更新します。
